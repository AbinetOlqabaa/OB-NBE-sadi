# NBE Central Bank Simulator Microservice & Temporary Integration Guide
**Application**: Oromia Bank NBE Regulatory Reporting Platform  
**Target Regulator**: National Bank of Ethiopia (Bank Supervision Directorate - BSD)  
**Governing Directives**: NBE Directive BSD/03/2020 & SBR/2026  
**Licensed Institution Code**: `0000013` (Oromia Bank S.C.)  
**Microservice Project Path**: `/nbe_simulator_service`  
**Microservice Port**: `8001` (Configurable via `NBE_SIMULATOR_PORT`)  

---

## 1. Executive Summary & Architecture

The **NBE Intake Gateway Simulator** is an independent, dedicated Django microservice engineered to emulate the statutory return ingestion gateway of the National Bank of Ethiopia. 

### Core Architectural Principles
1. **Independent Django Project**:
   - Contains its own `manage.py`, `settings.py`, WSGI/ASGI handlers, and URL routing.
   - Operates on its own isolated SQLite persistence store (`simulator_db.sqlite3`).
   - Runs on its own development server process and dedicated port (`8001`).
2. **Strict Boundary Segregation**:
   - **The OB Frontend NEVER communicates directly with the simulator.**
   - All client UI actions (e.g. Maker submissions, Checker deliveries, simulator telemetry views) communicate exclusively with the Oromia Bank Backend (Port 3000 / 8000).
   - The Oromia Bank Backend communicates with the Simulator via a hardened **NBE Gateway / Adapter** layer (`backend/apps/nbe_gateway/gateway_service.py` and `src/services/nbeAdapter.ts`).
3. **Seamless Production Migration (Zero Frontend Rewrite)**:
   - The payload structure, authentication contracts, HTTP headers, idempotency models, and response envelopes generated by the adapter match the exact production specification of the National Bank of Ethiopia (`POST https://nbe.gov.et/api/v2/regulatory/gateway`).
   - Switching from the local simulator to live production requires updating a single environment variable (`NBE_GATEWAY_URL`) and attaching the central bank VPN / mTLS certificates. No frontend components or report workflows require modification.

## 3. Preserved NBE Statutory Payload Structure

The simulator validates and preserves the canonical Central Bank JSON envelope:

```json
{
  "ReturnKey": "POBEPE001",
  "InstCode": "0000013",
  "FinYear": 2026,
  "StartDate": "2026-01-01",
  "EndDate": "2026-01-31",
  "ReturnItemsList": [
    { "Code": "R01_C01", "Value": 12500000000 },
    { "Code": "R02_C01", "Value": 48500000000 },
    { "Code": "R03_C01", "Value": 61000000000 }
  ],
  "DynamicItemsList": [
    {
      "Area": 1,
      "Rows": [
        ["CUST-001", "Ethiopian Airlines Group", 1500000000, "PERFORMING"]
      ]
    }
  ],
  "Maker": {
    "id": "usr_mkr_01",
    "name": "Bekele Tadesse",
    "email": "bekele.tadesse@oromiabank.com"
  },
  "Checker": {
    "id": "usr_chk_01",
    "name": "Chaltu Gemechu"
  }
}
```

### Mandatory Headers
- `Content-Type`: `application/json`
- `Idempotency-Key`: `idemp_{submissionId}_v{version}` (enforces at-most-once processing)
- `X-Correlation-ID`: `corr_{submissionId}_{timestamp}`
- `X-Institution-Code`: `0000013`
- `Authorization`: `Bearer <token>` (simulates hardware-bound mTLS token)
- *(Optional)* `X-Simulator-Force-Scenario`: `ALWAYS_SUCCESS | VALIDATION_ERROR | TIMEOUT | SERVER_ERROR | AUTH_FAILURE`

## 4. Simulation Modes & Deterministic Test Triggers

The simulator microservice supports 6 runtime behavior scenarios:

### 1. `ALWAYS_SUCCESS` (HTTP 200 / 201)
- Validates the incoming statutory envelope against the specified report key.
- Issues an authoritative cryptographic receipt in the format:  
  `NBE-REC-YYYYMMDD-XXXX` (e.g. `NBE-REC-20260929-72FEE7`).
- Records the submission in the simulator database.

### 2. `VALIDATION_ERROR` (HTTP 422 Unprocessable Entity)
- Triggered automatically if mandatory fields are omitted, if `InstCode` is not `0000013`, or if `ReturnKey` is not one of the 24 supported returns.
- Also triggered if forced via scenario configuration or `X-Simulator-Force-Scenario: VALIDATION_ERROR`.
- Returns structured JSON:
```json
{
  "success": false,
  "statusCode": 422,
  "error": "Unprocessable Entity",
  "message": "Statutory return rejected: schema or regulatory validation checks failed.",
  "validationErrors": [
    "Simulated NBE Cross-Schedule Discrepancy: Return M_LCPLC001 variance detected against Prudential Directive BSD/03/2020 capital limits."
  ],
  "correlationId": "corr_...",
  "institutionCode": "0000013",
  "reportKey": "M_LCPLC001"
}
```

### 3. `AUTH_FAILURE` (HTTP 401 Unauthorized)
- Emulates central bank VPN or hardware-bound mTLS smart card certificate expiration/revocation.
```json
{
  "success": false,
  "statusCode": 401,
  "error": "Unauthorized",
  "message": "NBE Central Gateway: Mutual TLS client certificate invalid, expired, or untrusted.",
  "correlationId": "corr_..."
}
```

### 4. `TIMEOUT` (HTTP 504 Gateway Timeout)
- Simulates intake ingestion cluster delays exceeding client socket timeouts (30000ms deadline).
- Triggers adapter abort controllers and retry loops.

### 5. `SERVER_ERROR` (HTTP 500 Internal Server Error)
- Simulates database lock contention or cluster node failure in the central bank repository.
- Tests OB backend retry resilience and exponential backoff.

### 6. `RANDOM_FLAKY`
- Injects 30% intermittent failure rate and random network latency jitter (50ms–2000ms).

### Deterministic Test Triggers
For automated integration tests and regression suites, any request can deterministically force a specific response without altering global server state by supplying either:
- Request Header: `X-Simulator-Force-Scenario: <MODE>`
- Query Parameter: `?scenario=<MODE>`
- Body Parameter: `"forceScenario": "<MODE>"`

## 6. How OB Backend Communicates Through NBE Gateway/Adapter

The Oromia Bank core application never exposes raw external endpoints to the frontend.

1. **Submission Delivery Flow**:
   - Checker reviews and approves the report.
   - Maker initiates final regulatory delivery: `POST /api/regulatory/submissions/:id/deliver`.
   - The OB backend invokes `NbeGatewayService.transmit_submission()` (Python) or `nbeAdapter.deliverReport()` (TypeScript).
   - The adapter generates the canonical payload, attaches `Idempotency-Key` and `X-Correlation-ID`, and dispatches an HTTP POST request to the microservice on port 8001.
   - Upon receiving HTTP 200, the official receipt number is recorded on the submission, status transitions to `SENT`, and immutable audit entries are created.

2. **Telemetry & Simulator Controls**:
   - The React frontend requests `/api/nbe-simulator/gateway-health`, `/api/nbe-simulator/scenario`, etc. on Port 3000.
   - The OB backend server reverse-proxies these requests internally to `http://127.0.0.1:8001/api/v1/nbe-simulator/*`.
   - The client browser never establishes any connection to port 8001 directly.

## 7. Migration Plan to Live Production NBE Endpoints

When Oromia Bank transitions from the testing phase to live submission via the Central Bank's point-to-point IPsec VPN tunnel, the following procedure is followed:

1. **Configuration Update**:
   Update environment configuration in `.env`:
   ```bash
   # Switch from Simulator to Central Bank Production Gateway
   NBE_GATEWAY_URL="https://nbe.gov.et/api/v2/regulatory/gateway"
   NBE_GATEWAY_MODE="PRODUCTION_CENTRAL_BANK"
   NBE_MTLS_CERT_PATH="/etc/ssl/certs/oromiabank_nbe_mtls.crt"
   NBE_MTLS_KEY_PATH="/etc/ssl/private/oromiabank_nbe_mtls.key"
   ```
2. **Adapter Execution**:
   - `NbeGatewayService` detects `NBE_GATEWAY_URL` pointing to the central bank domain and attaches the hardware-bound client certificates to outbound requests.
   - The payload format (`ReturnItemsList`, `DynamicItemsList`, `InstCode`, `FinYear`) already matches NBE's intake contract verbatim.
   - Receipts issued by NBE's live gateway are ingested and stored in the exact same `Submission` fields.
3. **Zero Frontend & Workflow Rewriting**:
   - Maker workflows, Checker approval screens, revision histories, PDF seal generators, and audit log pipelines remain 100% untouched.
